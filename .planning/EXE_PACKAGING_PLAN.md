# SHOEPOS — Windows EXE Packaging Plan

**Status:** ready to execute · **Owner:** Opus session · **Written:** 2026-07-05
**Goal:** one double-clickable `SHOEPOS.exe` that runs the FastAPI server, serves the built
React client, opens the browser, and keeps its SQLite data next to the exe. LAN mode
(`--lan`) must keep working for tablets.

---

## 0. Decision record (do not re-litigate)

**Approach: PyInstaller, one-DIR mode, console window ON, data dir next to the exe.**

- **PyInstaller onedir** — output is a folder `build/SHOEPOS/` containing `SHOEPOS.exe`
  plus `_internal/`. Chosen over:
  - *onefile*: slower start (unpacks to %TEMP% every launch), far more antivirus
    false-positives, and the POS runs all day — startup convenience is irrelevant.
    If a single distributable file is wanted, zip the folder or add Inno Setup (Phase 4).
  - *Nuitka*: faster runtime but a heavier, fussier toolchain (C compiler). No benefit —
    the app is I/O bound on SQLite.
  - *Electron/Tauri wrapper*: pointless here. The client is a browser SPA and tablets
    connect over LAN; there is no need for a desktop shell.
- **console=True for v1** — the black window doubles as the "server is running" indicator
  and closing it stops the server. A tray app (pystray) is a listed future upgrade, not v1.
- **Data next to the exe** (`<folder>\data\shoepos.db`) — matches the existing
  backup/restore story ("replace the .db file"), keeps everything on one laptop, and
  survives reinstalls if the folder is kept. `SHOEPOS_DATA_DIR` env override stays.
- **Client build is embedded** in the bundle (read-only, under `_internal/client_dist`).
  Dev mode (`npm run dev` + `python run.py`) must keep working unchanged.

## 2. Execution — Wave 1: two parallel subagents

The two tracks touch **disjoint files** — run them as parallel subagents (Sonnet/Opus
tier only, never Haiku). ⚠ This folder is **not a git repo**, so worktree isolation is
unavailable — disjoint file lists are the isolation. **No git operations, ever** (global
rule #1); if the user wants version control they will `git init` themselves.

### Track A — make the server freeze-aware
Files: `server/app/config.py`, `server/run.py` (nothing else).

1. **`config.py`** — resolve paths differently when frozen. Sketch (adapt, keep the
   existing constants below the paths untouched):
   ```python
   import os, sys
   from pathlib import Path

   FROZEN = bool(getattr(sys, "frozen", False))
   # PyInstaller: read-only assets live in _MEIPASS (in onedir this is <exe dir>/_internal);
   # mutable data must live OUTSIDE the bundle, next to the exe.
   _BUNDLE = Path(getattr(sys, "_MEIPASS", "."))
   SERVER_DIR = Path(sys.executable).resolve().parent if FROZEN else Path(__file__).resolve().parent.parent

   DATA_DIR = Path(os.environ.get("SHOEPOS_DATA_DIR", "") or SERVER_DIR / "data")
   DB_PATH = DATA_DIR / "shoepos.db"
   SCHEMA_PATH = (_BUNDLE / "app" / "schema.sql") if FROZEN else Path(__file__).resolve().parent / "schema.sql"
   CLIENT_DIST = (_BUNDLE / "client_dist") if FROZEN else SERVER_DIR.parent / "client" / "dist"
   ```
2. **`run.py`** —
   - `multiprocessing.freeze_support()` as the first statement of `__main__` (uvicorn
     pulls in multiprocessing; onefile relaunch loops are the classic failure).
   - Import the app object directly — `from app.main import app; uvicorn.run(app, ...)`.
     The current string form `uvicorn.run("app.main:app")` re-imports by name and is the
     #1 cause of frozen-app "module not found" failures.
   - **Single-instance guard**: before starting, try an HTTP/socket connect to
     `127.0.0.1:<port>`; if something is already listening, print a notice, open the
     browser to it, and exit 0 (double-clicking the exe twice must not crash-loop).
   - **Auto-open browser** when frozen: `threading.Timer(1.5, webbrowser.open,
     [f"http://127.0.0.1:{port}"])` before `uvicorn.run`; respect a `--no-browser` flag.
   - Keep `--lan` / `SHOEPOS_HOST` / `SHOEPOS_PORT` behavior exactly as-is (port 8899 is
     deliberate — 8787 belongs to KHALIFA POS; see run.py docstring, keep it).
3. **Acceptance (Track A verifies itself before returning):** `server\.venv\Scripts\python
   server\run.py` still boots and serves http://127.0.0.1:8899 in dev mode, and
   `npm run dev` proxying still works. Frozen behavior is verified in Wave 2, not here.

### Track B — packaging infrastructure
Files: `packaging/shoepos.spec`, `packaging/icon.ico` (optional), `scripts/build-exe.ps1`,
`README.md` (new section only).

1. **`packaging/shoepos.spec`** — Analysis of `../server/run.py`; note PyInstaller resolves
   spec-relative paths against SPECPATH:
   ```python
   a = Analysis(
       ["../server/run.py"],
       pathex=["../server"],                       # so `from app.main import app` resolves
       datas=[("../server/app/schema.sql", "app"),
              ("../client/dist", "client_dist")],
       hiddenimports=[],                           # add only what the build proves missing
   )
   pyz = PYZ(a.pure)
   exe = EXE(pyz, a.scripts, exclude_binaries=True, name="SHOEPOS",
             console=True, icon="icon.ico")        # drop icon= if no .ico is made
   coll = COLLECT(exe, a.binaries, a.datas, name="SHOEPOS")
   ```
2. **`scripts/build-exe.ps1`** (Windows PowerShell 5.1 — **no `&&`**, use `if ($?)` or
   separate statements; fail fast on each step):
   1. `client`: `npm install` (ci if lockfile) → `npm run build` (this runs `tsc --noEmit`).
   2. `server`: create `.venv` if missing → `pip install -r requirements.txt` →
      `pip install pyinstaller` (add `pyinstaller` to a new `server/requirements-build.txt`
      rather than polluting `requirements.txt`).
   3. `pyinstaller --noconfirm --distpath build --workpath build\_work packaging\shoepos.spec`
      run from the repo root.
   4. Print the output path and size summary.
3. **`packaging/icon.ico`** — optional; generate a simple flat shoe/tag glyph with Pillow
   or skip (spec then omits `icon=`). Do not spend more than a few minutes here.
4. **`README.md`** — add a "Build the EXE" section: run `scripts\build-exe.ps1`, result in
   `build\SHOEPOS\`, data lives in `build\SHOEPOS\data\` (or wherever the folder is copied),
   restore = stop exe, replace `data\shoepos.db`, start. Note the SmartScreen warning for
   unsigned exes ("More info → Run anyway") — signing is out of scope for v1.

## 3. Wave 2 — build, smoke-test, fix (leader, sequential)

This part is inherently sequential — frozen-import bugs only surface at build/run time.
Do NOT parallelize; use the debug-before-second-fix rule.

1. Run `scripts\build-exe.ps1`. Fix build errors at the root cause (usually a `datas` path
   or a genuine hidden import — add to the spec, not sys.path hacks).
2. Smoke-test the exe **with an isolated data dir** so the dev DB is untouched:
   `$env:SHOEPOS_DATA_DIR = "$env:TEMP\shoepos-smoke"; .\build\SHOEPOS\SHOEPOS.exe --no-browser`
   - `GET /` → 200, serves the SPA index (proves bundled `client_dist` found).
   - `POST /api/auth/login` with `admin` / PIN `0000` → session token (proves schema.sql
     bundled, DB seeded in the fresh data dir).
   - `GET /api/bootstrap` with that session → full state JSON.
   - Kill the process; confirm `shoepos.db` exists in the smoke data dir.
3. Re-verify **dev mode still works** (`python run.py` from `server/`, plus `npm run dev`).
4. Double-click test: launch the exe with no env vars — browser opens to the app, `data\`
   appears next to the exe. Launch it a second time while running → opens browser, no crash.
5. `--lan` test if a second device is handy; otherwise confirm it binds 0.0.0.0
   (`netstat -ano | findstr 8899`).

## 4. Phase 3+ (only if the user asks)

- **Inno Setup installer** (`packaging/installer.iss`): installs the onedir folder to
  Program Files, Start-menu shortcut, keeps `data\` in %LOCALAPPDATA%\SHOEPOS instead
  (needs the config default switched when installed to a read-only location).
- **Tray app / hidden console** (pystray + logging to `data\logs\`).
- **Code signing** to kill the SmartScreen warning.
- **Auto-start with Windows** (shortcut in shell:startup).

## 5. Risks / gotchas checklist

- [ ] Uvicorn string import fails frozen → import app object directly (Track A).
- [ ] `schema.sql` not bundled → seeding crashes on first boot (spec `datas`).
- [ ] Writing into `_internal/` — never; DB must stay outside the bundle.
- [ ] Antivirus flags: onedir mitigates; if Defender eats the exe during build, add the
      `build/` folder to exclusions on THIS machine only — do not tell users to disable AV.
- [ ] `npm run build` runs `tsc --noEmit` — type errors block the build; fix them, don't skip.
- [ ] WAL files: manual restore instructions must say "stop the server first" (WAL/SHM are
      merged on clean close; the in-app backup endpoint already uses the safe backup API).
- [ ] Port 8899 already in use by a non-SHOEPOS process → single-instance guard opens the
      browser to *whatever* is there; acceptable for v1, note in README.
